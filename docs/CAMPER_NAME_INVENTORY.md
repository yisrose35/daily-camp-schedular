# Where Campistry still identifies a camper by name

Generated by `node scripts/camper_name_inventory.js`. Do not edit by hand:
`tests/camper_name_inventory.test.js` fails when this file is out of date, and
when any number below goes **up**. The move to camper numbers is finished when
every number here is zero.

## What is already on camper numbers

- **Numbers are issued by the server**, one per camper, never shared, never re-issued while the camper's records exist (migration 253).
- **Every database function** that names a camper also takes the number, and the number decides who the camper is — including a camper who has left while a new child has their name (248, 257).
- **Parents' bills, saved cards and payment plans** find the family by the children's numbers (255). **Face data, photo tags and forms** are matched by number (256).
- **Every call and every row the pages send** that names a camper carries the number too, from every page including Campistry Lite (campistry_camper_id_rpc.js).
- **The canteen** finds a camper's account by number on the Snacks page, so a rename no longer shows an empty account.
- `scripts/verify_identity_chain.sql` checks all of this on the live database.

### 7. Database: storage keyed by a camper's name (4)

Every table that stores a camper also stores their number (223) and every function decides by it (248, 255-257). These are the places where the NAME is still the key:

- **Canteen accounts are keyed by name (camp_canteen_accounts.account_key).** Key accounts by person_id; keep the name as a label. 227 explains why the key stayed: old sales that carry only a name join through it — stamp those with the number first.
- **Parent invitations list children by name (link_parent_invites.camper_names).** Make person_ids the list and camper_names a label; 223 already stamps the numbers position by position.
- **Families list children by name (camp_families.camper_ids).** Make person_ids (234) the membership list and drop the name list once the Me page writes numbers.
- **Saved camp documents keyed by the roster key (camp_state_kv: roster, bunks, health, go addresses).** Follows the page steps below: when the pages key by number, the documents do too.

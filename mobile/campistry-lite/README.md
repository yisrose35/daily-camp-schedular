# Campistry Lite — mobile app shell

Native iOS + Android wrapper around the staff companion (`campistry_lite.html`
and `campistry_lite_login.html` at the repo root), built with
[Capacitor](https://capacitorjs.com). This folder is a self-contained Node
project — it doesn't touch the root `package.json` or the rest of the
(no-build-step) Campistry codebase. Same structure as
`mobile/campistry-link`; read that README too, most of it applies here.

**There is exactly one source of truth for the app's HTML/CSS/JS: the files at
the repo root.** This project never contains a hand-edited copy — `www/` is
generated by `scripts/sync-www.js` and is gitignored.

## Layout

- `capacitor.config.json` — app ID (`com.campistry.lite`), display name, splash/status-bar config
- `scripts/sync-www.js` — copies the repo-root Lite files into `www/`, then **verifies the bundle is complete** (see below)
- `android/`, `ios/` — the native projects (committed; build output is gitignored)

## Setup

```
cd mobile/campistry-lite
npm install
npm run sync        # populates www/, then `cap sync` copies it + plugins into android/ + ios/
```

Re-run `npm run sync` after any change to a repo-root Lite file.

## Building without a Mac (and without Android Studio)

Both platforms build in GitHub Actions — see `.github/workflows/mobile-android.yml`
and `.github/workflows/mobile-ios.yml`. Run either from the Actions tab.

- **Android** → downloads as a debug `.apk` artifact you can sideload onto a phone.
- **iOS** → compiles unsigned by default (proves it builds, needs no Apple account).
  Once you have an Apple Developer membership and add the secrets listed at the
  top of the iOS workflow, run it with `upload: true` and the build lands in
  **TestFlight** — which is how you install it on your own iPhone from Windows.

Capacitor 8's iOS project is Swift Package Manager-based, so there is no
CocoaPods step and nothing about maintaining `ios/` requires macOS.

## Bundle-completeness check

The native app **bundles** its web assets — there is no server to 404 against, so
a file that didn't get copied is a blank screen on a real phone. After copying,
`sync-www.js` scans every bundled HTML/JS/CSS file for same-repo references and
fails the build if one isn't in `www/`. If you add a `<script>` or an image to a
Lite page, the sync will tell you to add it to `FILES` rather than letting a
broken build reach a device.

Pages that deliberately live outside the bundle (`dashboard.html`, the desktop
app) are listed in `EXTERNAL_OK` and are opened in the system browser at runtime.

## Native-specific behavior

All of it lives in `campistry_lite_capacitor.js` at the repo root, guarded on
`Capacitor.isNativePlatform()` so the file is a complete no-op on the web.

- **Status bar** — opaque, tinted to the Lite coral shell.
- **Links that leave the bundle** — Settings' "Open full Campistry ↗" points at
  `dashboard.html`, which is *not* bundled. Natively that would dead-end the
  WebView with no way back short of force-quitting, so these links are
  intercepted and opened in the system browser against the live site.
- **Android hardware back button** — closes the account menu, then any open
  bottom sheet, then (since Lite already routes app/settings navigation through
  `history.pushState`) delegates to `history.back()`, and finally exits the app
  from the home launcher.
- **Biometric app lock** — Lite's lock uses **WebAuthn**, which does not work in
  a native WebView (Android's WebView has no WebAuthn; iOS WKWebView won't serve
  it to a `capacitor://` origin). Left alone, the Face ID / fingerprint lock
  silently reports "not available" on exactly the devices it was built for. On
  native only, the glue swaps the two capability checks and two crypto calls for
  `@aparajita/capacitor-biometric-auth`, writing the **same** `localStorage` keys
  `campistry_lite_biometric.js` reads — so `isEnabled` / `isEnabledFor` /
  `saveSession` / `disable` and every caller in `campistry_lite.js` keep working
  untouched. `NSFaceIDUsageDescription` is set in `ios/App/App/Info.plist`
  (without it, iOS reports Face ID unavailable).
- **Supabase SDK** — `campistry_lite.html` loads the SDK from jsDelivr on the
  web, but the vendored `supabase-js@2.js` when native: a CDN fetch is the one
  request that must succeed before anything renders, and camp reception is not
  something to bet the app's cold start on.

## Not done yet

1. **App icon and splash art.** Still Capacitor's defaults — there is no
   1024×1024 source art in the repo (`Campistry_logo.png` is 30×43,
   `Lite_clean.png` is an 816×388 wordmark). Drop a 1024×1024 `resources/icon.png`
   and a 2732×2732 `resources/splash.png` in, then:
   ```
   npm install --save-dev @capacitor/assets
   npm run assets && npm run sync
   ```
2. **Re-lock on resume.** `CAMPISTRY_LITE.md` describes the biometric lock firing
   on boot *and on resume*; only the boot path exists in the code today (the
   login page's biometric pane). Adding resume-lock needs an in-app lock overlay
   — `@capacitor/app`'s `appStateChange` is the hook.
3. **Push notifications** — nothing today. Needs `@capacitor/push-notifications`
   plus APNs/FCM setup.
4. **Signing, store accounts, and listings** — Apple Developer Program ($99/yr)
   and Google Play Console ($25 one-time), `com.campistry.lite` reserved on both,
   a release keystore for Android (**back it up — losing it means you can never
   update the Play listing again**), screenshots, and a privacy policy URL that
   honestly reflects the camper medical/contact data this app displays.
5. **Nothing has run on a real device yet.** Everything above is scaffolding and
   code review; the first CI build is the first real test.

## Bundle ID / app name

`com.campistry.lite` / "Campistry Lite" (set in `capacitor.config.json`, already
propagated into `android/app/src/main/res/values/strings.xml` and
`ios/App/App/Info.plist`). **Confirm before the first store submission — the
bundle ID can't be changed afterward without shipping as a new app.**

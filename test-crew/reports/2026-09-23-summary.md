## Broken (most serious first)

### 🔴 The test browser can't reach campistry.org at all
Rachel's browser refused the connection to `https://campistry.org` with a certificate-trust error, before any Campistry page — not even the login screen — ever appeared. She tried twice, restarting the browser in between, with the identical result both times.

**This is not a Campistry bug, and it does not mean the live site is down.** I independently re-tested this myself, outside Rachel's session, and reproduced the exact same failure. Here's what's actually going on: the cloud sandbox this test runs in routes all outbound web traffic through a security proxy (standard for this kind of environment). The browser that the test crew uses doesn't have that proxy's certificate marked as trusted, so every HTTPS connection — to any site, not just Campistry — gets rejected before a page can render. I confirmed the connection itself succeeds (it reaches the proxy fine); it's purely a "this one test browser doesn't trust this one certificate" problem, local to this test setup.

I looked for a safe way to fix it myself and couldn't: the tool needed to add the certificate to the browser's trust store (`certutil`) isn't installed, and installing it is blocked because this environment's package sources only work over plain HTTP, which the security proxy doesn't allow through. That combination means this needs a one-time fix in the environment's own configuration (its setup script), not something fixable from inside a test run. Once that's in place, `/test-crew` should get through the door and run its actual missions normally — nothing about Campistry itself was implicated here.
